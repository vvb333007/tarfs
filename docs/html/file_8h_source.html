72/* VFS handlers below are normally invoked through a VFS.
73 *
74 * On systems without VFS support, applications should call the tarfs_(),
75 * tarf_() and tard_() APIs directly. Unlike their POSIX counterparts, these
76 * functions take an additional first argument: an index of the mounted
77 * filesystem
78 *
79 * Typical usage without a VFS:
80 *
81 * 1. Mount the filesystem and save its identifier.
82 *
83 * int ctx = tarfs_mount(...);
84 * if (ctx < 0)
85 * exit_error("failed to mount filesystem");
86 *
87 * 2. Use the context pointer in subsequent filesystem calls.
88 *
89 * int fd1 = tarf_open((void *)ctx, "/home/file1.txt", flags);
90 * int fd2 = tarf_open((void *)ctx, "/home/file2.txt", flags);
91 * int fd3 = tarf_open((void *)ctx, "/home/file3.txt", flags);
92 */

97/* close()
98 * FS has at least 1 extra ref, because of open()
99 *
100 * close() is not thread-safe. It is not as bad as it seems: no crashes, no sigsegv.
101 * Just DO NOT close() files being read() at the same time by another thread. Or, if you do,
102 * do not open another file immediately :)
103 *
104 * This is because of:
105 *
106 * Closing a file descriptor while another thread is executing read()
107 * (or any operation using the same descriptor) is undefined behaviour.
108 *
109 * Since file descriptor slots are immediately reusable, a concurrent
110 * open() may repurpose the same slot for another file before the running
111 * operation completes, causing it to access the newly opened file instead
112 * of the original one.
113 *
114 */
